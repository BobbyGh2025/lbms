   836→// Journal/ledger double-entry architecture. Money uses Prisma `Decimal`
   837→// (stored as TEXT in SQLite for dev; migrates to DECIMAL(18,2) on
   838→// PostgreSQL/MySQL with zero schema change). Balances are DERIVED from
   839→// posted JournalEntries — there is no mutable `currentBalance` field.
   840→//
   841→//   FinancialAccount  (where money lives: cash/bank/momo)
   842→//          ↓
   843→//   LedgerAccount      (chart of accounts: income/expense/asset categories)
   844→//          ↓
   845→//   Journal            (one financial event; header)
   846→//          ↓
   847→//   JournalEntry       (debit/credit lines; MUST balance: Σ debit = Σ credit)
   848→//          ↓
   849→//   Reporting Service  (single source of truth for balances/summaries)
   850→//          ↓
   851→//   Dashboard / Reports / Exports
   852→// ============================================================================
   853→
   854→// Account types classify the nature of a financial account.
   855→//   asset      — cash, bank, mobile money (debit-normal: debits increase)
   856→//   liability  — payables, loans (credit-normal: credits increase)

   858→//   income     — revenue categories (credit-normal)

   871→  status        String   @default("active") // active | inactive
   872→  description   String?
   873→  bankName      String?

  1002→// A single debit OR credit line within a Journal. Exactly one of
  1003→// (debit, credit) is non-zero per entry. The journal is balanced when
  1004→// Σ(debit) = Σ(credit) across all its entries.
  1005→//
  1006→// `financialAccountId` is OPTIONAL: only entries that move money in/out of
  1007→// a cash/bank/momo account reference a FinancialAccount. The counter-side
  1008→// (e.g. an income category credit, or an expense category debit) references
  1009→// only a LedgerAccount. This mirrors real accounting where income/expense
  1010→// categories are not "accounts you hold money in".
  1011→model JournalEntry {
  1012→  id                String   @id @default(cuid())
  1013→  journalId         String
  1014→  journal           Journal  @relation(fields: [journalId], references: [id], onDelete: Cascade)
  1015→
  1016→  financialAccountId String?
  1017→  financialAccount   FinancialAccount? @relation(fields: [financialAccountId], references: [id], onDelete: Restrict)
  1018→
  1019→  ledgerAccountId   String?
  1020→  ledgerAccount     LedgerAccount? @relation(fields: [ledgerAccountId], references: [id], onDelete: Restrict)
  1021→
  1022→  // Exactly one of debit/credit is non-zero (the other is 0). Both Decimal.
  1023→  debit  Decimal @default(0)
  1024→  credit Decimal @default(0)
  1025→  currency String @default("GHS")
  1026→
  1027→  description String?
  1028→  createdAt   DateTime @default(now())
  1029→
  1030→  @@index([journalId])
  1031→  @@index([financialAccountId])
  1032→  @@index([ledgerAccountId])
  1033→}

  1567→// Inventory becomes the authoritative operational record for stock AFTER goods
  1568→// are physically received. The flow is:
  1569→//
  1570→//   Procurement:  Request → PurchaseOrder → GoodsReceipt
  1571→//                                              ↓

  1581→//   GoodsReceiptItem.inventoryPostedAt marker + StockMovement @@unique on
  1582→//   (referenceType, referenceId) — a single goods receipt item can produce
  1583→//   at most one inventory receipt movement.
