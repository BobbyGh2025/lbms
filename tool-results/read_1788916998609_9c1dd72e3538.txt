     1→     1→# API Reference
     2→     2→
     3→     3→This document is the complete reference for every HTTP endpoint exposed by
     4→     4→LBMS in Phase 1. All endpoints are JSON-only. All endpoints except
     5→     5→NextAuth's session/credential callbacks require a valid NextAuth session
     6→     6→cookie.
     7→     7→
     8→     8→---
     9→     9→
    10→    10→## 1. Conventions
    11→    11→
    12→    12→### Base URL
    13→    13→
    14→    14→- Development: `http://localhost:3000` (when running `bun run dev`).
    15→    15→- Caddy gateway: `http://localhost:81` (see `DEPLOYMENT.md`).
    16→    16→
    17→    17→### Authentication
    18→    18→
    19→    19→All endpoints except `/api/auth/*` require a valid NextAuth session cookie
    20→    20→(`next-auth.session-token`). Anonymous requests receive HTTP 401:
    21→    21→
    22→    22→```json
    23→    23→{ "error": "Authentication required." }
    24→    24→```
    25→    25→
    26→    26→### Authorization
    27→    27→
    28→    28→Each endpoint documents the required permission as `module:action` (e.g.
    29→    29→`users:view`). The MD role (`session.user.isMD === true`) bypasses every
    30→    30→permission check. Non-MD users without the required permission receive
    31→    31→HTTP 403:
    32→    32→
    33→    33→```json
    34→    34→{ "error": "You are not authorized to perform this action." }
    35→    35→```
    36→    36→
    37→    37→### Error envelope
    38→    38→
    39→    39→All errors use the same shape:
    40→    40→
    41→    41→```json
    42→    42→{
    43→    43→  "error": "Human-readable error message.",
    44→    44→  "code": "optional machine code",
    45→    45→  "details": "optional extra context (Zod issues, structured payload)"
    46→    46→}
    47→    47→```
    48→    48→
    49→    49→Status codes used:
    50→    50→
    51→    51→| Status | Meaning |
    52→    52→| --- | --- |
    53→    53→| 200 | OK — GET or successful PATCH / PUT |
    54→    54→| 201 | Created — POST that created a resource |
    55→    55→| 400 | Bad Request — Zod validation, JSON parse, uniqueness clash, business-rule guard |
    56→    56→| 401 | Unauthorized — no session |
    57→    57→| 403 | Forbidden — session present but missing permission, or self-delete / last-MD guard |
    58→    58→| 404 | Not Found — record not found or soft-deleted |
    59→    59→| 500 | Internal Server Error — unexpected (never returns a stack trace) |
    60→    60→
    61→    61→### Pagination
    62→    62→
    63→    63→List endpoints accept `page` and `pageSize` query params. Defaults:
    64→    64→`page = 1`, `pageSize = 20`. `pageSize` is clamped to `1..100`.
    65→    65→
    66→    66→Response shape:
    67→    67→
    68→    68→```json
    69→    69→{
    70→    70→  "items": [ /* records */ ],
    71→    71→  "total": 150,
    72→    72→  "page": 1,
    73→    73→  "pageSize": 20
    74→    74→}
    75→    75→```
    76→    76→
    77→    77→### Content type
    78→    78→
    79→    79→- All request bodies must be `application/json`.
    80→    80→- All responses are `application/json; charset=utf-8`.
    81→    81→
    82→    82→### Dynamic route params
    83→    83→
    84→    84→Next.js 16 Route Handlers receive dynamic params as a Promise:
    85→    85→
    86→    86→```ts
    87→    87→{ params }: { params: Promise<{ id: string }> }
    88→    88→```
    89→    89→
    90→    90→Inside the handler the params are awaited. Clients send the `id` as a
    91→    91→URL path segment (`/api/users/cx...`).
    92→    92→

   113→   113→## 3. Auth (NextAuth)
   114→   114→
   115→   115→These endpoints are provided by the NextAuth route handler at
   116→   116→`src/app/api/auth/[...nextauth]/route.ts`. The configuration lives in
   117→   117→`src/lib/auth.ts`.
   118→   118→
   119→   119→### `POST /api/auth/callback/credentials`
   120→   120→
   121→   121→Sign in with email + password. The body is form-encoded by the NextAuth
   122→   122→client (`signIn("credentials", { email, password })`), not JSON.
   123→   123→
   124→   124→- **Auth**: anonymous (this is the sign-in endpoint).
   125→   125→- **Body**: `email=...&password=...&csrfToken=...` (form-encoded).
   126→   126→- **Success**: HTTP 302 redirect to the `callbackUrl` (default `/`); sets
   127→   127→  the `next-auth.session-token` cookie.
   128→   128→- **Failure**: HTTP 401, returns to the sign-in page with an `error`
   129→   129→  query param.
   130→   130→- **Side effects**:
   131→   131→  - On success: writes `AuditLog` entry `action=login, module=auth`,
   132→   132→    resets `failedLoginAttempts=0`, `lockedUntil=null`, updates
   133→   133→    `lastLoginAt` + `lastLoginIp`.
   134→   134→  - On failure: writes `AuditLog` entry `action=login_failed,
   135→   135→    module=auth`. If the attempt count reaches 5, sets `lockedUntil =
   136→   136→    now + 15min`.
   137→   137→
   138→   138→### `GET /api/auth/session`
   139→   139→
   140→   140→Returns the current session as JSON, or `{}` if not signed in.
   141→   141→
   142→   142→- **Auth**: anonymous.
   143→   143→- **Response (signed in)**:
   144→   144→  ```json
   145→   145→  {
   146→   146→    "user": {
   147→   147→      "id": "cx...",
   148→   148→      "email": "md@lightworld.tech",
   149→   149→      "name": "md",
   150→   150→      "username": "md",
   151→   151→      "roles": ["md"],
   152→   152→      "permissions": ["dashboard:view", "users:view", ...],
   153→   153→      "isMD": true
   154→   154→    },
   155→   155→    "expires": "2025-01-01T00:00:00.000Z"
   156→   156→  }
   157→   157→  ```
   158→   158→
   159→   159→### `GET /api/auth/csrf`
   160→   160→
   161→   161→Returns the CSRF token + cookie. Required before calling
   162→   162→`POST /api/auth/callback/credentials`.
   163→   163→
   164→   164→- **Auth**: anonymous.
   165→   165→- **Response**: `{ "csrfToken": "..." }`.
   166→   166→
   167→   167→### `POST /api/auth/signout`
   168→   168→
   169→   169→Signs the user out. Clears the session cookie.
   170→   170→
   171→   171→- **Auth**: requires a valid session.
   172→   172→- **Body**: `csrfToken=...` (form-encoded).
   173→   173→- **Side effect**: writes `AuditLog` entry `action=logout, module=auth`
   174→   174→  (best-effort via the `events.signOut` callback).
   175→   175→

   274→   274→## 7. Users
   275→   275→
   276→   276→### `GET /api/users`
   277→   277→
   278→   278→Paginated list of non-soft-deleted users. Never returns `passwordHash`.
   279→   279→
   280→   280→- **Auth**: `users:view`.
   281→   281→- **Query**: `page`, `pageSize`, `search` (matches `email` or `username`
   282→   282→  via `contains`), `status` (`active | inactive | suspended | all`).
   283→   283→- **Response**:
   284→   284→  ```json
   285→   285→  {
   286→   286→    "items": [
   287→   287→      {
   288→   288→        "id": "cx...",
   289→   289→        "email": "md@lightworld.tech",
   290→   290→        "username": "md",
   291→   291→        "status": "active",
   292→   292→        "lastLoginAt": "2025-01-01T00:00:00.000Z",
   293→   293→        "lastLoginIp": "127.0.0.1",
   294→   294→        "mustChangePassword": false,
   295→   295→        "createdAt": "...",
   296→   296→        "updatedAt": "...",
   297→   297→        "employee": { "id": "cx...", "employeeId": "LT-EMP-0001", "fullName": "Lightworld MD" },
   298→   298→        "roles": [ { "id": "cx...", "name": "md", "displayName": "Managing Director" } ]
   299→   299→      }
   300→   300→    ],
   301→   301→    "total": 2,
   302→   302→    "page": 1,
   303→   303→    "pageSize": 20
   304→   304→  }
   305→   305→  ```
   306→   306→
   307→   307→### `POST /api/users`
   308→   308→
   309→   309→Create a new user. Hashes the password with bcrypt cost 10.
   310→   310→
   311→   311→- **Auth**: `users:create`.
   312→   312→- **Body**:
   313→   313→  ```json
   314→   314→  {
   315→   315→    "email": "user@lightworld.tech",
   316→   316→    "username": "user",
   317→   317→    "password": "password123",
   318→   318→    "employeeId": "cx...",
   319→   319→    "roleIds": ["cx..."],
   320→   320→    "status": "active"
   321→   321→  }
   322→   322→  ```
   323→   323→  - `email`: required, must be a valid email.
   324→   324→  - `username`: required, min 3 chars.
   325→   325→  - `password`: required, min 8 chars.
   326→   326→  - `employeeId`: optional; if provided, must point to an active/on_leave
   327→   327→    employee not already linked to another live user.
   328→   328→  - `roleIds`: array of role IDs; defaults to `[]`. All must exist and not
   329→   329→    be soft-deleted.
   330→   330→  - `status`: optional; defaults to `active`. One of
   331→   331→    `active | inactive | suspended`.
   332→   332→- **Success**: HTTP 201 with the created user (same shape as a list item,
   333→   333→  plus `employeeId`).
   334→   334→- **Errors**:
   335→   335→  - 400 if email or username already exists (with a different message
   336→   336→    for soft-deleted collisions).
   337→   337→  - 400 if any role ID is invalid.
   338→   338→  - 400 if the employee is missing or already linked.
   339→   339→- **Audit**: `action=create, module=users, recordType=User, newValue=<user>`.
   340→   340→
   341→   341→### `GET /api/users/:id`
   342→   342→
   343→   343→Fetch a single user.
   344→   344→
   345→   345→- **Auth**: `users:view`.
   346→   346→- **Success**: 200 with the user object (includes `employeeId`).
   347→   347→- **Errors**: 404 if the user is missing or soft-deleted.
   348→   348→
   349→   349→### `PATCH /api/users/:id`
   350→   350→
   351→   351→Partial update of a user. `passwordHash` is re-hashed when `password` is
   352→   352→provided.
   353→   353→
   354→   354→- **Auth**: `users:edit`.
   355→   355→- **Body** (any subset):
   356→   356→  ```json
   357→   357→  {
   358→   358→    "email": "...",
   359→   359→    "username": "...",
   360→   360→    "status": "active | inactive | suspended",
   361→   361→    "employeeId": "cx..." | null,
   362→   362→    "password": "..."
   363→   363→  }
   364→   364→  ```
   365→   365→- **Guards**:
   366→   366→  - At least one field must be provided (Zod `.refine`).
   367→   367→  - Email / username uniqueness is re-checked (excluding the row itself).
   368→   368→  - Re-linking an employee validates that the employee is not already
   369→   369→    linked to another live user.
   370→   370→  - **Last-MD guard**: if the user is an MD (`role.name === "md"`) and the
   371→   371→    requested `status` is not `active`, the endpoint counts MD users
   372→   372→    (excluding this one); if the count is `<= 1`, returns 400
   373→   373→    `"Cannot deactivate or suspend the last Managing Director account."`.
   374→   374→- **Success**: 200 with the updated user.
   375→   375→- **Audit**: `action=update, module=users, recordType=User`,
   376→   376→  `previousValue` + `newValue` (both exclude `passwordHash`).
   377→   377→
   378→   378→### `DELETE /api/users/:id`
   379→   379→
   380→   380→Soft-delete a user. Sets `deletedAt`, `status="inactive"`, `employeeId=null`.
   381→   381→
   382→   382→- **Auth**: `users:delete`.
   383→   383→- **Guards**:
   384→   384→  - Cannot delete self (`403 You cannot delete your own account.`).
   385→   385→  - **Last-MD guard**: if the user is an MD and is the only MD, returns
   386→   386→    `403 Cannot delete the last Managing Director account.`
   387→   387→- **Success**: 200 with `{ "id": "...", "deletedAt": "..." }`.
   388→   388→- **Audit**: `action=delete, module=users, recordType=User`,
   389→   389→  `previousValue=<user>`.
   390→   390→
   391→   391→### `GET /api/users/:id/roles`
   392→   392→
   393→   393→List the user's role assignments.
   394→   394→
   395→   395→- **Auth**: `users:view`.
   396→   396→- **Response**:
   397→   397→  ```json
   398→   398→  {
   399→   399→    "items": [
   400→   400→      {
   401→   401→        "id": "cx...",
   402→   402→        "name": "md",
   403→   403→        "displayName": "Managing Director",
   404→   404→        "isSystem": true,
   405→   405→        "assignedAt": "2025-01-01T00:00:00.000Z"
   406→   406→      }
   407→   407→    ]
   408→   408→  }
   409→   409→  ```
   410→   410→
   411→   411→### `PUT /api/users/:id/roles`
   412→   412→
   413→   413→Replace the user's roles atomically.
   414→   414→
   415→   415→- **Auth**: `users:edit`.
   416→   416→- **Body**: `{ "roleIds": ["cx...", "cx..."] }`
   417→   417→- **Behaviour**: de-duplicates the array, validates each ID exists and is
   418→   418→  not soft-deleted, then within a `$transaction` deletes all existing
   419→   419→  `UserRole` rows for the user and recreates the new set.
   420→   420→- **Audit**: `action=update, module=users, recordType=User`,
   421→   421→  `previousValue={ roleIds: [...] }`, `newValue={ roleIds: [...] }`.
   422→   422→
   423→   423→### `POST /api/users/:id/reset-password`
   424→   424→
   425→   425→Reset a user's password. Hashes the new password, clears lockout state.
   426→   426→
   427→   427→- **Auth**: `users:edit`.
   428→   428→- **Body**: `{ "password": "newpassword" }` (min 8 chars).
   429→   429→- **Side effects**:
   430→   430→  - `passwordHash` replaced (bcrypt cost 10).
   431→   431→  - `failedLoginAttempts = 0`, `lockedUntil = null`,
   432→   432→    `mustChangePassword = false`.
   433→   433→- **Response**: `{ "ok": true }`.
   434→   434→- **Audit**: `action=update, module=users, recordType=User,
   435→   435→  description="Password reset for <username> (<email>)"`. The new password
   436→   436→  is **never** included in the audit payload.
   437→   437→
   438→   438→### `GET /api/users/employees`
   439→   439→
   440→   440→Thin picker for the user form. Returns active / on_leave employees that
   441→   441→are not currently linked to a live user.
   442→   442→
   443→   443→- **Auth**: `users:view`.
   444→   444→- **Query**: `includeEmployeeId=<id>` (optional; the Edit form passes
   445→   445→  this so the currently-linked employee is included in the list).
   446→   446→- **Response**:
   447→   447→  ```json
   448→   448→  {
   449→   449→    "items": [
   450→   450→      {
   451→   451→        "id": "cx...",
   452→   452→        "employeeId": "LT-EMP-0001",
   453→   453→        "fullName": "Lightworld MD",
   454→   454→        "departmentName": "Management"
   455→   455→      }
   456→   456→    ]
   457→   457→  }
   458→   458→  ```
   459→   459→
   460→   460→### `GET /api/users/roles`
   461→   461→
   462→   462→Thin picker for the user form. Returns all non-deleted roles.
   463→   463→
   464→   464→- **Auth**: `users:view`.
   465→   465→- **Response**:
   466→   466→  ```json
   467→   467→  {
   468→   468→    "items": [
   469→   469→      {
   470→   470→        "id": "cx...",
   471→   471→        "name": "md",
   472→   472→        "displayName": "Managing Director",
   473→   473→        "isSystem": true,
   474→   474→        "description": "Full access..."
   475→   475→      }
   476→   476→    ]
   477→   477→  }
   478→   478→  ```

   488→   488→
   489→   489→- **Auth**: `roles:view`.
   490→   490→- **Response**:
   491→   491→  ```json
   492→   492→  {
   493→   493→    "items": [
   494→   494→      {
   495→   495→        "id": "cx...",
   496→   496→        "name": "md",
   497→   497→        "displayName": "Managing Director",
   498→   498→        "description": "Full access...",
   499→   499→        "isSystem": true,
   500→   500→        "createdAt": "...",
   501→   501→        "permissions": [
   502→   502→          { "id": "cx...", "module": "users", "action": "view" }
   503→   503→        ],
   504→   504→        "_count": { "users": 1 }
   505→   505→      }
   506→   506→    ]
   507→   507→  }
   508→   508→  ```
   509→   509→
   510→   510→### `POST /api/roles`
   511→   511→
   512→   512→Create a new role + an initial permission set.
   513→   513→
   514→   514→- **Auth**: `roles:create`.
   515→   515→- **Body**:
   516→   516→  ```json
   517→   517→  {
   518→   518→    "name": "team_lead",
   519→   519→    "displayName": "Team Lead",
   520→   520→    "description": "...",
   521→   521→    "permissionKeys": ["users:view", "tasks:view", "tasks:edit"]
   522→   522→  }
   523→   523→  ```
   524→   524→  - `name`: regex `^[a-z][a-z0-9_]*$` — lowercase, no spaces, starts with
   525→   525→    a letter.
   526→   526→  - `displayName`: min 2 chars.
   527→   527→  - `permissionKeys`: array of `"module:action"` strings. Unknown keys are
   528→   528→    dropped silently with a `console.warn`.
   529→   529→- **Soft-deleted restore**: if a soft-deleted role with the same `name`
   530→   530→  exists, the endpoint restores it (re-uses the row id) instead of
   531→   531→  failing the unique constraint.
   532→   532→- **Success**: HTTP 201 with the created role (same shape as a list item).
   533→   533→- **Audit**: `action=create, module=roles, recordType=Role,
   534→   534→  newValue={ name, displayName, description, permissionKeys }`.
   535→   535→
   536→   536→### `GET /api/roles/:id`
   537→   537→
   538→   538→Fetch a single role with its full permission list + user count.
   539→   539→
   540→   540→- **Auth**: `roles:view`.
   541→   541→- **Errors**: 404 if missing or soft-deleted.
   542→   542→
   543→   543→### `PATCH /api/roles/:id`
   544→   544→
   545→   545→Update `displayName` and/or `description` only. The role `name` cannot
   546→   546→be changed via this endpoint (it is the canonical key in the JWT).
   547→   547→
   548→   548→- **Auth**: `roles:edit`.
   549→   549→- **Body**: `{ "displayName": "...", "description": "..." | null }`
   550→   550→  (at least one field required).
   551→   551→- **Audit**: `action=update, module=roles, recordType=Role`.
   552→   552→
   553→   553→### `DELETE /api/roles/:id`
   554→   554→
   555→   555→Hard-delete a non-system role with no users assigned. Cascades
   556→   556→`RolePermission` and `UserRole` rows.
   557→   557→
   558→   558→- **Auth**: `roles:delete`.
   559→   559→- **Guards**:
   560→   560→  - 400 if `isSystem === true` — `"System roles cannot be deleted."`.
   561→   561→  - 400 if `_count.users > 0` — `"Role has N user(s) assigned; reassign
   562→   562→    them first."`.
   563→   563→- **Response**: `{ "id": "...", "deleted": true }`.
   564→   564→- **Audit**: `action=delete, module=roles, recordType=Role,
   565→   565→  previousValue={ name, displayName, description, isSystem }`.
   566→   566→
   567→   567→### `GET /api/roles/:id/permissions`
   568→   568→
   569→   569→Return the role's current permission keys as `"module:action"` strings.
   570→   570→
   571→   571→- **Auth**: `roles:view`.
   572→   572→- **Response**: `{ "permissionKeys": ["users:view", ...] }`.
   573→   573→
   574→   574→### `PUT /api/roles/:id/permissions`
   575→   575→
   576→   576→Replace the role's entire permission set atomically.
   577→   577→
   578→   578→- **Auth**: `roles:edit`.
   579→   579→- **Body**: `{ "permissionKeys": ["users:view", ...] }`.
   580→   580→- **Behaviour**: de-duplicates keys, validates each against the canonical
   581→   581→  catalogue (unknown keys dropped + logged), resolves to `Permission` IDs,
   582→   582→  then within a `$transaction` deletes all existing `RolePermission` rows
   583→   583→  for the role and recreates the new set.
   584→   584→- **Response**:
   585→   585→  ```json
   586→   586→  {
   587→   587→    "permissionKeys": ["users:view", ...],
   588→   588→    "skippedCount": 0
   589→   589→  }
   590→   590→  ```
   591→   591→- **Audit**: `action=update, module=roles, recordType=RolePermission,
   592→   592→  previousValue={ permissionKeys: [...] },
   593→   593→  newValue={ permissionKeys: [...], skippedCount: 0 }`.
   594→   594→

   626→   626→## 10. Departments
   627→   627→
   628→   628→### `GET /api/departments`
   629→   629→
   630→   630→List non-soft-deleted departments with position + employee counts.
   631→   631→
   632→   632→- **Auth**: `departments:view`.
   633→   633→- **Query**: `search` (matches `name`), `status` (`active | inactive`).
   634→   634→- **Response**:
   635→   635→  ```json
   636→   636→  {
   637→   637→    "items": [
   638→   638→      {
   639→   639→        "id": "cx...",
   640→   640→        "name": "Management",
   641→   641→        "code": "MGMT",
   642→   642→        "description": "Executive management office.",
   643→   643→        "status": "active",
   644→   644→        "createdAt": "...",
   645→   645→        "_count": { "positions": 2, "employees": 1 }
   646→   646→      }
   647→   647→    ]
   648→   648→  }
   649→   649→  ```
   650→   650→- **Note**: `_count.positions` and `_count.employees` use Prisma filtered
   651→   651→  counts so soft-deleted children are excluded.
   652→   652→
   653→   653→### `POST /api/departments`
   654→   654→
   655→   655→Create a department.
   656→   656→
   657→   657→- **Auth**: `departments:create`.
   658→   658→- **Body**: `{ "name": "Engineering", "code": "ENG", "description": "..." }`
   659→   659→  - `name`: required, max 100 chars, unique among non-deleted.
   660→   660→  - `code`: optional; if provided, uppercased and must be unique.
   661→   661→  - `description`: optional.
   662→   662→- **Success**: HTTP 201 with the created department.
   663→   663→- **Audit**: `action=create, module=departments, recordType=Department,
   664→   664→  newValue=<dept>`.
   665→   665→
   666→   666→### `GET /api/departments/:id`
   667→   667→
   668→   668→Fetch a single department with its positions (sorted by title) and counts.
   669→   669→
   670→   670→- **Auth**: `departments:view`.
   671→   671→- **Response**: the department object plus a `positions[]` array; each
   672→   672→  position carries `_count.employees`.
   673→   673→
   674→   674→### `PATCH /api/departments/:id`
   675→   675→
   676→   676→Update a department.
   677→   677→
   678→   678→- **Auth**: `departments:edit`.
   679→   679→- **Body** (any subset): `{ "name", "code", "description", "status" }`
   680→   680→  - `status` restricted to `active | inactive`.
   681→   681→  - `code` uppercased; null / empty string normalises to `null`.
   682→   682→- **Guards**: name + code uniqueness re-checked (excluding self). At least
   683→   683→  one field required.
   684→   684→- **Audit**: `action=update, module=departments, recordType=Department,
   685→   685→  previousValue + newValue`.
   686→   686→
   687→   687→### `DELETE /api/departments/:id`
   688→   688→
   689→   689→Soft-delete a department.
   690→   690→
   691→   691→- **Auth**: `departments:delete`.
   692→   692→- **Guards**: 400 if the department has active employees or positions —
   693→   693→  the response body includes `{ activeEmployees, activePositions }` so the
   694→   694→  UI can show actionable guidance:
   695→   695→  ```json
   696→   696→  {
   697→   697→    "error": "Cannot delete a department that still has active employees or positions. Reassign or remove them first.",
   698→   698→    "details": { "activeEmployees": 3, "activePositions": 2 }
   699→   699→  }
   700→   700→  ```
   701→   701→- **Behaviour**: sets `deletedAt = now()` and `status = "inactive"`.
   702→   702→- **Audit**: `action=delete, module=departments, recordType=Department,
   703→   703→  previousValue=<dept>`.

   789→   789→  ```json
   790→   790→  {
   791→   791→    "companyName": "Lightworld Tech",
   792→   792→    "legalName": "Lightworld Tech Ltd",
   793→   793→    "logoUrl": "https://...",
   794→   794→    "address": "...",
   795→   795→    "city": "Accra",

   797→   797→    "country": "Ghana",
   798→   798→    "phone": "+233 ...",
   799→   799→    "email": "info@lightworld.tech",
   800→   800→    "website": "https://...",
   801→   801→    "currency": "GHS",
   802→   802→    "currencySymbol": "GH₵",
   803→   803→    "financialYearStart": "01-01",

   810→   810→  - `currency`: must be exactly 3 uppercase letters (regex `^[A-Z]{3}$`).

   822→   822→## 13. Audit
   823→   823→
   824→   824→The audit resource is **read-only** by design. There are no
   825→   825→`POST`/`PATCH`/`DELETE` endpoints.
   826→   826→
   827→   827→### `GET /api/audit`
   828→   828→
   829→   829→Paginated, filterable list of audit log entries.
   830→   830→
   831→   831→- **Auth**: `audit:view`.
   832→   832→- **Query**:
   833→   833→  - `page`, `pageSize` — standard pagination.
   834→   834→  - `search` — matches `description` via `contains`.
   835→   835→  - `module` — exact match (e.g. `users`, `auth`, `departments`).
   836→   836→  - `action` — exact match (one of `login | logout | login_failed |
   837→   837→    create | update | delete | approve | reject | view_sensitive |
   838→   838→    export | system`).
   839→   839→  - `userId` — exact match.
   840→   840→  - `from` — ISO date or date-time; lower bound on `createdAt`.
   841→   841→  - `to` — ISO date or date-time; upper bound on `createdAt`. **Note**: if
   842→   842→    `to` is a date-only string (`YYYY-MM-DD`), the upper bound is advanced
   843→   843→    by 24 hours so the entire day is covered (SQLite stores full ISO
   844→   844→    timestamps).
   845→   845→- **Response**:
   846→   846→  ```json
   847→   847→  {
   848→   848→    "items": [
   849→   849→      {
   850→   850→        "id": "cx...",
   851→   851→        "userId": "cx...",
   852→   852→        "action": "login",
   853→   853→        "module": "auth",
   854→   854→        "recordId": null,
   855→   855→        "recordType": null,
   856→   856→        "description": "User md signed in",
   857→   857→        "ipAddress": "127.0.0.1",
   858→   858→        "userAgent": "Mozilla/...",
   859→   859→        "previousValue": null,
   860→   860→        "newValue": null,
   861→   861→        "createdAt": "2025-01-01T00:00:00.000Z",
   862→   862→        "user": { "id": "cx...", "email": "md@lightworld.tech", "name": "md" }
   863→   863→      }
   864→   864→    ],
   865→   865→    "total": 150,
   866→   866→    "page": 1,
   867→   867→    "pageSize": 20
   868→   868→  }
   869→   869→  ```
   870→   870→- **Marked `dynamic = "force-dynamic"`** so the response is never cached.
   871→   871→
   872→   872→### `GET /api/audit/stats`
   873→   873→
   874→   874→Lightweight summary used by the audit view header.
   875→   875→
   876→   876→- **Auth**: `audit:view`.
   877→   877→- **Response**:
   878→   878→  ```json
   879→   879→  {
   880→   880→    "total": 150,
   881→   881→    "last24h": 12,
   882→   882→    "byModule": { "auth": 4, "users": 3, "departments": 2, "settings": 1 },
   883→   883→    "byAction": { "login": 4, "create": 3, "update": 3, "delete": 1 }
   884→   884→  }
   885→   885→  ```
   886→   886→- `byModule` is the top 8 modules by count.
   887→   887→- `byAction` is all actions.

   892→   892→
   893→   893→| Status | `error` | When |

   899→   899→| 400 | `"Cannot delete a department that still has active employees or positions..."` with `details = { activeEmployees, activePositions }` | Department DELETE guard |
   900→   900→| 400 | `"System roles cannot be deleted."` | Role DELETE on system role |
   901→   901→| 400 | `"Role has N user(s) assigned; reassign them first."` | Role DELETE with users assigned |
   902→   902→| 400 | `"Cannot deactivate or suspend the last Managing Director account."` | Users PATCH last-MD guard |
   903→   903→| 401 | `"Authentication required."` | No session |
   904→   904→| 401 | `"Unauthorized"` | Dashboard / notifications (legacy short form) |
   905→   905→| 403 | `"You are not authorized to perform this action."` | Missing permission, non-MD |
   906→   906→| 403 | `"You cannot delete your own account."` | Self-delete |
   907→   907→| 403 | `"Cannot delete the last Managing Director account."` | Last-MD delete guard |
   908→   908→| 404 | `"User not found."` / `"Role not found."` / `"Department not found."` / `"Position not found."` | Record missing or soft-deleted |
   909→   909→| 500 | (generic message) | Unexpected server error — never a stack trace |
